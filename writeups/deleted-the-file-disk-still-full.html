Deleted the file. Disk still full.

1 min read

I deleted a 20 GB log file on a Linux server and the disk was still full. For a moment I thought the server was lying to me.

Here’s what was actually happening.

On Linux, deleting a file only removes its name. The actual data stays on disk as long as any program still has that file open. In my case, the service writing the log was still running and happily writing into a file that no longer had a name.

So the disk space never came back until that program let go of the file.

How to catch it:

  • Run lsof +L1 to list files that are deleted but still open
  • You’ll see which program is holding them
DeleteOnly the name goesThe data stays on disk
Still openA program holds itSpace stays used
Let goRestart the serviceSpace comes back

How to fix it:

  • Restart that service so it releases the file
  • Next time, empty the log file instead of deleting it, so the program keeps writing into the same file
  • Better still, set up log rotation so this never gets out of hand

A small detail about how Linux handles files, but it explains so many “disk full” mysteries.
