One reboot and the cameras swapped

1 min read

After a routine reboot, a multi camera system came back up with no errors. Every stream was live. Every model was running.

And the front camera’s frames were being processed with the rear camera’s calibration, zones and rules.

Nothing had crashed. The cameras had simply swapped names.

On Linux, device numbers like /dev/video0 and /dev/video2 are handed out in the order devices are detected at boot. That order isn’t guaranteed. Drivers initialize in parallel, USB devices enumerate in different sequences, and one slow device can shift every number after it. The same goes for serial ports, which is how GPS receivers and other sensors quietly end up reading from the wrong port.

If your code or config says “camera 0 is the front camera”, you’re relying on luck.

What I do on every multi sensor device:

  • Never refer to devices by index in code or config
  • Write udev rules that match each device by something stable, like its serial number or the physical port it’s plugged into
  • Give each one a readable, permanent name, for example:
SUBSYSTEM=="video4linux", ATTRS{serial}=="A1B2C3", SYMLINK+="cam_front"
  • Check at startup that every expected device name exists, and fail loudly if one is missing instead of silently using the next camera

It’s a five minute fix that prevents some of the hardest to spot bugs in the field, because everything looks healthy while the data is quietly wrong.

Never trust /dev/video0 to be the same camera twice.
