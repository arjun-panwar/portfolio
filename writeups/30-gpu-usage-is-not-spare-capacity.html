Video pipelines and performance

30% GPU usage is not spare capacity

1 min read

“The GPU is only at 30%, so we can add more cameras.” I’ve heard this many times, and it’s almost always wrong.

We had a system exactly like that. GPU utilization looked low, yet the pipeline was already dropping frames. Adding streams made it worse, not better.

When we timed every stage of a single frame, the picture was clear. Inference on the GPU was one of the shortest steps. Most of the time went into decoding video, converting colors, resizing, copying data to the GPU and postprocessing results. Almost all of that ran on the CPU, and one core was pinned at 100%. The GPU sat idle most of the time, simply waiting for frames.

Utilization tells you how busy a device is. It doesn’t tell you where your bottleneck is.

What I do before deciding a system has capacity:

  • Time every stage per frame, including decode, color conversion, copies and postprocessing, not just the model
  • Look at per core CPU usage, not the average. One saturated core can limit the whole pipeline while the total looks fine
  • Move heavy work to where it belongs: hardware video decode, and preprocessing on the GPU so frames stay in GPU memory
  • Overlap the stages, so the GPU works on one frame while the CPU prepares the next
  • Test capacity by adding real streams until latency breaks, instead of trusting a percentage
